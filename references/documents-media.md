# Documents, spreadsheets, PDFs, and presentations

## General path

Use the supplied template when one exists. Generate an editable source first, then export/preview. Preserve formulas in spreadsheets, native equations where required, captions and cross-references, and the difference between editable content and a flattened preview.

## DOCX / PDF

Check headings, page breaks, fonts, margins, line spacing, table overflow, equations, images, captions, references, and PDF page rendering. A PDF parser can verify text and metadata, but visual inspection is still needed for layout. Track fonts and rendering engine when portability matters.

## XLSX

Keep raw/input, calculation, and presentation sheets distinct. Use formulas rather than pasted totals; define units and missing-value rules; check representative formulas and recalculate in a spreadsheet engine when available. State when formulas were not recalculated by a compatible engine.

## PPTX / Beamer / HTML

One message per slide: claim, evidence/visual, and speaker action. Use readable font sizes, consistent units and labels, an agenda/roadmap, source notes, speaker notes where requested, and a timed rehearsal. Export PDF or rendered images for visual QA when the host permits. A generated slide file is not proof it was presented or editable in the target application.

## Handwritten or photographed presentation

Treat handwriting texture as a display style. It must not be used to misrepresent unperformed work, an original handwritten submission, or an unavailable experiment. Keep the editable source and label synthetic examples.
