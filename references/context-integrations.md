# Discipline, preferences, continuation, and connected tools

## Discipline adaptation

Choose the method from the actual course and rubric. These are starting points, not universal chapter templates:

| Task family | Evidence and method to preserve | Important check |
|---|---|---|
| Language, literature, history, philosophy | Textual evidence, contextual interpretation, original sources, competing readings | Distinguish interpretation from a quoted fact; verify edition and page |
| Social science, education, management, economics | Research question, concepts, qualitative coding or empirical design, sampling, alternatives | Separate correlation from causation; avoid invented interviews or surveys |
| Mathematics and theoretical science | Definitions, assumptions, proof/derivation, domain and boundary cases | Each inference follows; solution satisfies original conditions |
| Mechanical, electrical, civil and other engineering | Technical specification, calculation/model, units, circuit/CAD/model files and tests | Appropriate versions, views, loads/constraints and stated limits |
| Computing and data science | Requirements, data/model/code, reproducible build, evaluation and error cases | Split/data leakage, real execution, dependency versions |
| Chemistry, biology, medicine and experimental science | Protocol, raw measurements, uncertainty, statistical/biological interpretation | Trace observations, distinguish simulation, never imply unperformed validation |
| Art, architecture, design and practical courses | Brief, references, process, editable artifacts, presentation and critique | Design meets the brief; document actual process rather than inventing it |

For a specialist tool such as MATLAB, SPSS, R, ANSYS, SolidWorks or a CAD suite, check the version and available interface before choosing native outputs. If native execution is unavailable, retain editable source or a documented interchange format and identify what still needs local verification. A different format does not satisfy an explicit native-format requirement without the user's acceptance.

## Confirmed preferences and ongoing work

Use preferences already confirmed in the conversation. Distinguish user decisions from inferred defaults. Store them in a task-local profile only when persistent files or the host's memory feature are available and their use is within the user's requested scope. Do not write a global profile or credentials as a side effect of ordinary homework.

Keep these fields when relevant: course/level, language, explanation depth, writing samples and observed style, template, citation standard/version, tool constraints, confirmed decisions, and date. Keep defaults marked `proposed`; update them when the user corrects them. Do not infer a permanent major from one assignment.

For a long project, keep a compact continuation note containing: task brief, inputs and file locations, decisions and assumptions, completed outputs, commands and evidence, outstanding questions, and the next action. Load it on resumption before repeating work. When the host cannot persist memory, provide a copyable note; do not promise future recall.

## Literature and citation managers

Use supplied PDFs and reference-manager exports first when appropriate. With a supported, authorized Zotero connection, search/read the selected library; add or modify entries only within the user's requested action. Without a connector, work from exported BibTeX/BibLaTeX/RIS/CSL-JSON or a supplied source table and return an importable file using only verified metadata.

For CNKI or another academic database, use accessible records, user-supplied exports, or an available authorized connection. Record how a source was verified; having a title from a search result does not mean its full argument was read. Keep abstract-only review distinct from full-text reading. Preserve unavailable fields as unresolved rather than inventing DOI, page, issue or publisher data.

Follow the school/journal's requested citation standard and edition (for example, GB/T 7714, APA, MLA, Chicago, IEEE or Vancouver). Use one consistent style, preserve source IDs across revisions, and verify that bibliography entries and in-text citations match.

## Course platforms and external actions

Reading a user-selected course resource through an existing connector is different from changing grades, sending a message, uploading a submission, or clicking submit. Check which action the user actually authorized. A broad request to design this Skill does not authorize later account actions.

For Canvas or another course platform, use the host's existing authenticated connector when available; prepare files and check due dates, course/assignment identity, allowed formats and the submission package. Submit only with applicable explicit user authorization and a working connection. Reuse valid authorization rather than asking again without cause. Record the actual outcome or receipt; never report a submission from a prepared file alone. When no connection exists, deliver the package and a short manual submission checklist.
